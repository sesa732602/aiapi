# API服务平台数据库实体关系设计

## 核心实体

### 1. 用户实体
- 用户基本信息
- 认证信息
- 账户状态

### 2. API接口实体
- 接口基本信息
- 接口参数
- 接口返回值
- 接口文档

### 3. 鉴权实体
- API密钥
- 权限控制
- 速率限制

### 4. 套餐实体
- 套餐类型
- 价格策略
- 使用限制

### 5. 订单实体
- 订单信息
- 支付状态
- 关联套餐

### 6. 日志实体
- 请求日志
- 调用统计
- 错误记录

### 7. 账单实体
- 消费记录
- 余额变动
- 账单明细

## 实体关系

1. **用户 - API密钥**: 一对多关系，一个用户可以拥有多个API密钥
2. **用户 - 套餐**: 多对多关系，通过订单表关联
3. **用户 - 订单**: 一对多关系，一个用户可以有多个订单
4. **套餐 - API接口**: 多对多关系，一个套餐可以包含多个API接口，一个API接口可以属于多个套餐
5. **用户 - 日志**: 一对多关系，一个用户可以有多个API调用日志
6. **API接口 - 日志**: 一对多关系，一个API接口可以有多个调用日志
7. **用户 - 账单**: 一对多关系，一个用户可以有多个账单记录
8. **订单 - 账单**: 一对多关系，一个订单可以关联多个账单记录（如分期付款）

## 数据流向

1. 用户注册/登录 -> 生成API密钥 -> 选择套餐 -> 创建订单 -> 支付 -> 使用API
2. API调用 -> 鉴权验证 -> 速率检查 -> 记录日志 -> 计费 -> 更新账单
3. 用户查询 -> 获取日志/账单/API使用情况 -> 展示数据

此设计确保了各功能模块之间的数据流转清晰，同时保持了良好的扩展性和维护性。
