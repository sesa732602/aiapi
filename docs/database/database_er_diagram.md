# API服务平台数据库ER图说明文档

## 1. 系统概述

本文档详细描述API服务平台的数据库实体关系设计，包括各表之间的主外键关系、核心字段和数据流向。该平台旨在提供API服务管理、用户认证、接口文档、鉴权、代理、套餐售卖等功能。

## 2. 核心实体关系图

```
+-------------+       +------------+       +-------------+
|    用户     |-------|  API密钥   |-------|   API接口   |
+-------------+       +------------+       +-------------+
      |                                          |
      |                                          |
+-------------+       +------------+       +-------------+
|    套餐     |-------|   订单     |       |   API文档   |
+-------------+       +------------+       +-------------+
      |                     |                    |
      |                     |                    |
+-------------+       +------------+       +-------------+

+-------------+       +------------+       +-------------+
      |                     |
      |                     |
+-------------+       +------------+

+-------------+       +------------+

                           |
                      +------------+

                      +------------+
```

## 3. 模块关系详解

### 3.1 用户与认证模块

#### 核心表：
- `users`: 用户基本信息
- `oauth_accounts`: 第三方认证信息
- `user_verifications`: 用户验证信息
- `user_sessions`: 用户会话
- `password_resets`: 密码重置
- `user_settings`: 用户配置
- `roles`: 角色定义
- `user_roles`: 用户-角色关联

#### 主要关系：
- 一个用户可以有多个第三方认证账号（一对多）
- 一个用户可以有多个验证记录（一对多）
- 一个用户可以有多个会话（一对多）
- 一个用户可以有多个密码重置记录（一对多）
- 一个用户有一个用户配置（一对一）
- 用户和角色是多对多关系，通过`user_roles`关联

#### 数据流向：
1. 用户注册 -> 创建用户记录 -> 生成验证记录
2. 用户登录 -> 创建会话 -> 加载用户配置和角色
3. 第三方登录 -> 关联或创建用户 -> 创建会话

### 3.2 API接口与文档模块

#### 核心表：
- `apis`: API接口基本信息
- `api_parameters`: API参数
- `api_responses`: API响应
- `api_docs`: API文档
- `sdk_examples`: SDK示例代码
- `api_error_codes`: API错误码
- `api_versions`: API版本历史
- `api_categories`: API分类
- `api_category_relations`: API-分类关联
- `api_tags`: API标签
- `api_tag_relations`: API-标签关联

#### 主要关系：
- 一个API可以有多个参数（一对多）
- 一个API可以有多个响应（一对多）
- 一个API可以有多个文档（一对多，按语言区分）
- 一个API可以有多个SDK示例（一对多，按编程语言区分）
- 一个API可以有多个错误码（一对多）
- 一个API可以有多个版本历史（一对多）
- API和分类是多对多关系，通过`api_category_relations`关联
- API和标签是多对多关系，通过`api_tag_relations`关联

#### 数据流向：
1. 创建API -> 添加参数和响应 -> 编写文档和SDK示例
2. 更新API -> 创建新版本记录 -> 更新文档

### 3.3 鉴权与权限模块

#### 核心表：
- `api_keys`: API密钥
- `permissions`: 权限定义
- `user_permissions`: 用户-权限关联
- `role_permissions`: 角色-权限关联
- `api_permissions`: API-权限关联
- `rate_limits`: 速率限制
- `rate_limit_counters`: 速率限制计数
- `ip_whitelist`: IP白名单
- `ip_blacklist`: IP黑名单
- `api_access_controls`: API访问控制

#### 主要关系：
- 一个用户可以有多个API密钥（一对多）
- 用户和权限是多对多关系，通过`user_permissions`关联
- 角色和权限是多对多关系，通过`role_permissions`关联
- API和权限是多对多关系，通过`api_permissions`关联
- 一个用户可以有多个速率限制（一对多）
- 一个用户可以有多个IP白名单记录（一对多）
- 一个API有一个访问控制配置（一对一）

#### 数据流向：
1. 用户注册 -> 分配角色 -> 继承角色权限
2. 用户创建API密钥 -> 设置速率限制
3. API调用 -> 检查密钥 -> 验证权限 -> 检查速率限制 -> 执行或拒绝

### 3.4 API代理与日志模块

#### 核心表：
- `proxy_configs`: 代理配置
- `custom_domains`: 自定义域名
- `domain_verifications`: 域名验证
- `request_logs_meta`: 请求日志元数据
- `log_storage_configs`: 日志存储配置
- `log_downloads`: 日志下载记录
- `gateway_nodes`: 网关节点
- `traffic_stats_daily`: 流量统计（按天）
- `traffic_stats_monthly`: 流量统计（按月）

#### 主要关系：
- 一个API有一个代理配置（一对一）
- 一个用户可以有多个自定义域名（一对多）
- 一个域名可以有多个验证记录（一对多）
- 一个用户可以有多个请求日志（一对多）
- 一个用户有一个日志存储配置（一对一）
- 一个用户可以有多个日志下载记录（一对多）

#### 数据流向：
1. 配置API代理 -> 创建代理配置
2. 用户添加自定义域名 -> 生成验证记录 -> 验证域名
3. API调用 -> 记录请求日志 -> 更新流量统计
4. 用户查看日志 -> 下载日志 -> 记录下载

### 3.5 套餐与计费模块

#### 核心表：
- `plans`: 套餐
- `plan_features`: 套餐特性
- `plan_apis`: 套餐-API关联
- `user_plans`: 用户套餐
- `user_api_quotas`: 用户API配额
- `orders`: 订单
- `order_items`: 订单项目
- `coupons`: 优惠券
- `order_coupons`: 订单-优惠券关联
- `pricing_strategies`: 价格策略
- `tiered_pricing`: 阶梯价格

#### 主要关系：
- 一个套餐可以有多个特性（一对多）
- 套餐和API是多对多关系，通过`plan_apis`关联
- 一个用户可以有多个套餐（一对多，通过`user_plans`）
- 一个用户可以有多个API配额（一对多）
- 一个用户可以有多个订单（一对多）
- 一个订单可以有多个订单项目（一对多）
- 订单和优惠券是多对多关系，通过`order_coupons`关联
- 一个API有一个价格策略（一对一）
- 一个价格策略可以有多个阶梯价格（一对多）

#### 数据流向：
1. 用户选择套餐 -> 创建订单 -> 支付 -> 激活用户套餐
2. 激活套餐 -> 更新用户API配额
3. API调用 -> 扣减配额 -> 超额计费

### 3.6 支付与账单模块

#### 核心表：
- `payments`: 支付记录
- `user_balances`: 用户余额
- `balance_transactions`: 余额交易
- `invoices`: 账单
- `invoice_items`: 账单明细
- `api_usage_stats_daily`: API使用统计（按日）
- `api_usage_stats_monthly`: API使用统计（按月）
- `billing_records`: 计费记录
- `payment_gateways`: 支付网关配置
- `refunds`: 退款记录
- `invoice_info`: 发票信息

#### 主要关系：
- 一个订单可以有多个支付记录（一对多）
- 一个用户有一个余额记录（一对一）
- 一个用户可以有多个余额交易（一对多）
- 一个用户可以有多个账单（一对多）
- 一个账单可以有多个账单明细（一对多）
- 一个用户可以有多个API使用统计（一对多）
- 一个用户可以有多个计费记录（一对多）
- 一个支付记录可以有多个退款记录（一对多）
- 一个用户可以有多个发票信息（一对多）

#### 数据流向：
1. 用户下单 -> 选择支付方式 -> 创建支付记录 -> 更新订单状态
2. 用户充值 -> 创建支付记录 -> 更新余额 -> 创建余额交易记录
3. API调用 -> 记录使用统计 -> 生成计费记录
4. 定期（月底）-> 汇总计费记录 -> 生成账单 -> 创建账单明细
5. 用户申请退款 -> 创建退款记录 -> 处理退款 -> 更新余额

## 4. 关键数据流程

### 4.1 用户注册与API使用流程

```
用户注册 -> 邮箱验证 -> 创建API密钥 -> 选择套餐 -> 支付订单 -> 
获得API配额 -> 调用API -> 鉴权验证 -> 速率检查 -> 
记录日志 -> 扣减配额 -> 超额计费 -> 生成账单
```

### 4.2 套餐购买与续费流程

```
浏览套餐 -> 选择套餐 -> 创建订单 -> 应用优惠券 -> 
选择支付方式 -> 完成支付 -> 更新订单状态 -> 
激活用户套餐 -> 更新API配额 -> 设置自动续费
```

### 4.3 账单生成与支付流程

```
API使用 -> 记录使用统计 -> 月底汇总 -> 生成账单 -> 
创建账单明细 -> 通知用户 -> 用户查看账单 -> 
选择支付方式 -> 完成支付 -> 更新账单状态
```

## 5. 索引优化策略

为提高查询效率，系统在以下关键字段上建立了索引：

1. 所有主键（PRIMARY KEY）
2. 所有外键（FOREIGN KEY）
3. 唯一约束字段（UNIQUE KEY）
4. 高频查询条件字段：
   - 用户表：email, phone, status
   - API密钥表：key, status
   - 订单表：order_number, status
   - 账单表：invoice_number, status
   - 日志表：request_time, response_status
   - 统计表：date, year_month
5. 复合索引：
   - 用户API配额表：(user_id, api_id)
   - 流量统计表：(user_id, api_id, date)
   - 速率限制计数表：(user_id, api_id, api_key_id, counter_key)

## 6. 数据库扩展性考虑

1. **分表策略**：
   - 日志表按用户和时间分表
   - 统计表按时间周期分表

2. **分区策略**：
   - 大型表（如请求日志）按时间范围分区
   - 用户相关表可按用户ID范围分区

3. **缓存策略**：
   - API密钥和权限信息适合缓存
   - 速率限制计数适合使用Redis等内存数据库

4. **备份策略**：
   - 交易数据定期备份
   - 日志数据可采用冷热存储策略

## 7. 数据安全考虑

1. **敏感数据加密**：
   - 密码使用哈希+盐存储
   - API密钥密文加密存储
   - 支付信息加密存储

2. **数据隔离**：
   - 用户日志独立存储
   - 不同用户的API调用数据严格隔离

3. **访问控制**：
   - 基于角色的权限控制
   - API访问基于多层鉴权机制
